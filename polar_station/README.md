# Полярная (арктическая) станция — учётная система

Десктопное приложение (tkinter) на Python, хранилище — SQLite.
Архитектура — MVC, ядро — ООП.

## Запуск
python main.py              # окно tkinter; БД polar_station.db создастся и заполнится демо-данными
python main.py --db my.db   # другой файл БД
python main.py --order-url http://адрес/order   # с внешней системой заказа

Демо-учётки: `boss / boss123` (руководитель), `observer / observer123` (наблюдатель,
привязан к метеорологу Петровой), `engineer / engineer123` (инженер, привязан к механику Козлову), `supervisor / supervisor123` (научный супервайзер, только чтение; ЛР4).

## Архитектура MVC

main.py                     сборка слоёв
model/                      ВСЯ бизнес-логика, не зависит от интерфейса
  entities.py               классы предметной области + самовалидация
  validation.py             проверки типов, диапазонов, дат
  security.py               роли, права (AccessPolicy), PBKDF2-хеши паролей
  repositories.py           SQL (только параметризованные запросы)
  services.py               сценарии: проверка прав → правила → транзакция
  database.py, seed.py      схема SQLite (+CHECK), демо-данные
view/gui_view.py            tkinter: окна, вкладки, таблицы, формы, окно ожидания (только виджеты)
controller/gui_controller.py  GUI: View → Model → View (вкладки, формы, фоновая отправка)

# ЛР4 — адаптация к новым требованиям (несколько станций, внешние системы, аудит)

Реализовано: **интеграция с внешней системой заказа продовольствия и медикаментов**
(требования 10–12), **журнал аудита** и роль **«супервайзер»** (требования 8–9),
**запрет планового ТО по погоде** (ветер > 15 м/с, температура < −45 °C) и **графический интерфейс**.

## Контракт внешней системы (допущение)
Запрос `POST`: `{"request_id", "item", "category", "quantity", "unit"}`.
Ответ: `{"status": "accepted"|"rejected", "order_ref", "delivery_days", "reason"}`.


## Аудит
Фиксируются действия руководителя и супервайзера (изменения данных и просмотр наблюдений
супервайзером): время, пользователь, роль, действие, объект, детали. Записи неизменяемы
(в коде нет методов правки, в БД — триггеры). Просмотр — пункт «Журнал аудита».


## Журнал аудита и окно
Просмотр наблюдений аудируемой ролью — действие «просмотр наблюдений». Чтобы автообновление
таблиц не засоряло журнал, вкладка «Измерения» обновляется только при её открытии и по кнопке
«Обновить» (одна запись аудита на открытие).

## Не реализовано (описано в отчёте)
Несколько станций (`station_id`), передача наблюдений в региональный центр, медосмотры.
